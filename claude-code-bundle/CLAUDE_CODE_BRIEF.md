## Design direction — Military / Tactical Operations aesthetic

**The brief in one sentence:** This is the dashboard of someone who runs production infrastructure. Not a tech-influencer portfolio.

**Palette (define as Tailwind theme tokens in `tailwind.config.ts`):**

```
Background:
  base       #0a0a0b    (near-black, slight warm tint)
  surface    #14151a    (cards, panels)
  surface-2  #1c1e26    (raised elements)
  border     #2a2d3a    (subtle dividers)

Foreground:
  text       #e6e6e1    (bone white, NOT pure white)
  text-dim   #9b9c97
  text-mute  #6a6b67

Accents:
  olive      #7a8450    (primary accent — buttons, links, brand)
  olive-dim  #555c38
  amber      #c08a3e    (warnings)
  rust       #a14b3a    (blockers/critical, NOT bright red)
  steel      #4a5568    (informational)

Semantic (for findings):
  status-blocker  → rust
  status-warning  → amber
  status-info     → steel
  status-ok       → olive
```

**Typography:**
- Body: Inter (already commonly used) or Geist Sans. Pick one, apply globally.
- Monospace: JetBrains Mono. Use for code blocks, data tables, technical identifiers, timestamps.
- No serif fonts anywhere.
- Headings: same family as body, weight 600 for h1, 500 for h2, normal weight for body.

**Component shape language:**
- **Hard edges by default.** `rounded-none` or `rounded-sm` max. No `rounded-xl` or `rounded-full` except in profile photos.
- **Thin 1px borders, never shadows.** `border border-border` not `shadow-lg`.
- **Section headers styled as classification banners:** thin horizontal rules above/below, monospace section labels, e.g. `// PROJECTS` or `[ TOOLS ]`.
- **Status badges look like rank insignia:** uppercase, monospace, thin border, no fill except a 1-2px coloured left border for severity.
- **Tables and data displays:** monospace fonts, dense rows, subtle alternating row backgrounds via `bg-surface` and `bg-surface-2`.

**Motion:**
- Page transitions: 150-200ms fade only. No slides, no springs.
- Hover states: immediate. No transition-duration > 100ms on hovers.
- ScanLine: keep available as accent on key headings only.
- DO NOT add: bouncy motion, parallax beyond what GalaxyCursor already does, glow effects, gradient animations.

**What to avoid (explicit don'ts):**
- Neon colours (no cyan, no magenta, no electric blue)
- Glassmorphism / backdrop-blur (except sparingly on the ChatWidget if needed)
- Large blurry gradient backgrounds
- Glow / shadow effects around text or buttons
- Animated gradients
- "Cyberpunk" anything

### STEP 8 — Create the Audit Viewer route

This is the biggest single piece of work. Read all of it before starting.

Create `src/app/tools/page.tsx` — index page listing tools (matches the landing section).

Create `src/app/tools/audit-viewer/page.tsx` — the audit viewer itself.

Create supporting components in `src/components/tools/audit-viewer/`:

- `DropZone.tsx` — drag-and-drop file area accepting `.json` files, multi-file support
- `FindingsSummary.tsx` — top-of-page summary card showing BLOCKER / WARN / INFO counts
- `FindingsList.tsx` — sortable/filterable list of findings across all loaded hosts
- `HostCard.tsx` — per-host card showing inventory + workload summary
- `InventoryPanel.tsx` — renders the inventory JSON (OS, hardware, network, volumes)
- `WorkloadPanel.tsx` — renders the workload JSON (SQL, apps, services, etc.)
- `AnonymiseToggle.tsx` — button to mask hostnames/IPs/usernames in the displayed data
- `DemoDataButton.tsx` — loads embedded sample data so portfolio visitors see populated content

**Functional requirements:**

1. **No backend.** Everything client-side. JSON parsed in the browser, nothing sent anywhere.
2. **Accepts two collector outputs per host:** inventory JSON and workload JSON. Recognise them by the `Metadata.CollectorName` field (`collect-server-inventory` vs `collect-workload-profile`). Merge by `Metadata.Hostname`.
3. **Multi-host:** dropping JSONs from 5 servers shows 5 host cards.
4. **Findings come from workload JSON.** Aggregate them at the top of the page. Sort by severity (Blocker → Warn → Info), then by host, then by category.
5. **Anonymise toggle replaces:**
   - Any value matching IPv4 regex → `xxx.xxx.xxx.xxx`
   - Hostnames in `Metadata.Hostname` → `HOST-01`, `HOST-02`, etc.
   - Usernames in `Metadata.CollectedBy` → `DOMAIN\user`
   - Domain values → `example.local`
6. **Demo data button:** ships with two embedded sample JSONs in `src/data/audit-viewer-demo.ts`. One server's inventory + workload. Realistic but sanitised — use `HOST-DEMO-01`, RFC1918 IPs, generic SQL DB names. Demonstrates: 1 blocker (zero CALs), 2 warnings (32-bit apps + large storage), 1 info finding.

**Visual requirements:**

- Page header: `// AUDIT VIEWER` monospace, brief intro paragraph, link to "How this works" (expandable section explaining the PowerShell collectors)
- DropZone: large dashed border, drop hint in monospace, supports click-to-browse
- Findings summary: three large counters across the top — BLOCKER count (rust), WARN count (amber), INFO count (steel)
- Findings list: monospace table, each row colour-coded by left border, expandable to show evidence
- Host cards: collapsible sections, one per hostname, expanding shows the inventory + workload data side-by-side
- Empty state (no data loaded): clear instructions + demo data button + link to download collector scripts

**Performance:**

- JSONs may be 200KB each — parsing is synchronous and fine
- Use `useReducer` for state if it grows, otherwise `useState`
- No need for virtualisation in this iteration (assume <50 hosts)

**File downloads from the page:**

Add a "Download Collectors" section on the audit viewer page with two buttons that download the PowerShell scripts. Place the scripts in `public/tools/audit-viewer/`:

- `public/tools/audit-viewer/collect-server-inventory.ps1` — exact content from `artefacts/collect-server-inventory.ps1`
- `public/tools/audit-viewer/collect-workload-profile.ps1` — exact content from `artefacts/collect-workload-profile.ps1`

Copy them VERBATIM. Do not modify. The download buttons link to these static paths.

**Commit:** `feat: add audit viewer tool with drag-and-drop JSON rendering, anonymise toggle, demo data, and collector script downloads`
